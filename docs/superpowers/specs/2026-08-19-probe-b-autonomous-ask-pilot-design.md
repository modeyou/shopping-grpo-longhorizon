# Probe B V3 低成本 Autonomous-Ask Pilot 设计

日期：2026-08-19

状态：已批准设计，待实现

## 1. 实验问题

Probe B V2 已证明：在购物前获得一个被隐藏的真实约束，可以将严格成功率从 76% 提高到 96%，同时不增加错误购买。V3 只验证下一层机制：

> 当模型拥有一次受限的自主提问机会时，它能否在购物前识别缺失的重要约束、提出命中该约束的问题，并利用回答恢复一部分 Oracle 上限？

V3 不测试长期用户画像，不声称估计自然任务中的总体提问率，也不重新检验 V2 的信息价值结论。

## 2. 固定范围与选择理由

采用 10 条定向 Pilot，而不是再次运行全部 25 条：

- 全部 6 条 `color`：`6935`、`13089`、`17319`、`18637`、`21175`、`21247`；
- V2 冻结随机顺序中最先出现的 4 条 `budget`：`5496`、`13871`、`20518`、`12403`。

执行顺序沿用 V2 的种子 `20260818` 并在上述集合中过滤，固定为：

`5496 → 17319 → 13871 → 20518 → 12403 → 21247 → 18637 → 6935 → 13089 → 21175`

选择规则在实现和 V3 真实运行前冻结。它覆盖 V2 增益最集中的全部颜色任务，并用固定顺序选择预算任务，避免按单题成败事后挑选。由于样本是定向的，结果只能决定是否继续开发自主澄清机制，不能外推为四类字段的总体效果。

## 3. 实验条件

V3 只新增一个 `autonomous_ask` 臂，共 10 条新轨迹。所选任务的 `no_ask` 和 `oracle_ask` 结果直接复用 V2 冻结运行 `oracle-v2-dsv4flash-01`，不重复付费。

三种条件的含义为：

- `no_ask`：V2 已有结果，模型看不到隐藏约束且不能提问；
- `autonomous_ask`：V3 新轨迹，模型可在首次购物动作前自主决定是否提问一次；
- `oracle_ask`：V2 已有结果，在首次购物动作前固定提供正确问答，作为可恢复上限。

V3 必须继续使用相同的 `deepseek-v4-flash` 模型名、温度 `0.0`、ShopSimulator Environment v2.1、Reward v3、observation v2、shop tool schema v2、任务文件及任务哈希。滚动模型名导致的服务端 revision 限制继续在结果中披露。

## 4. Autonomous-Ask 行为协议

### 4.1 提问时机与次数

每个任务最多调用一次 `ask_user`，且它只在模型产生第一个购物工具动作之前可见：

1. 第一次模型调用同时获得 `ask_user` 和标准购物工具；
2. 若模型直接选择购物工具，本任务永久关闭提问机会；
3. 若模型调用 `ask_user`，系统返回一次回答，然后立即移除该工具；
4. 后续模型调用只获得标准购物工具。

提问及回答不触碰 ShopSimulator，也不计入环境步数，但产生回答后的第二次模型调用仍计入 LLM 调用预算。模型在工具移除后虚构 `ask_user` 属于 Agent 行为问题，不算基础设施无效。

### 4.2 提问提示词

V3 使用独立、冻结并写入 manifest 哈希的系统提示词。它保留正式购物规则，只将“不得向用户追问”改为：若首次行动前发现一个会实质影响购买决定的重要约束缺失，可以调用一次 `ask_user` 询问一个简洁问题；否则直接购物。

提示词不得说明每条 Pilot 都刻意隐藏了一个字段，不得提示隐藏字段的类型，也不得包含任务答案。

### 4.3 工具接口

新增的本地工具仅包含一个参数：

```json
{
  "name": "ask_user",
  "arguments": {"question": "string"}
}
```

工具只由 V3 客户端适配器截获，不发送到 ShopSimulator。适配器把 assistant 工具调用及对应 tool 回答追加到同一条消息历史，再向底层模型请求首个购物动作。

若模型在同一回合返回多个工具调用，只保留第一个，其他调用记录为截断事件，与正式 rollout 的串行动作规则一致。

## 5. 确定性用户回答

回答器只使用任务中冻结的 `latent_goal` 和 `oracle_turn`，绝不向模型暴露 `clear_query`。

它在 Unicode casefold 后按子串匹配以下冻结关键词，将问题识别为 `budget`、`color`、`brand`、`origin` 中的零个、一个或多个字段：

- `budget`：`预算`、`价格范围`、`价位`、`多少钱`、`最高价格`、`价格上限`；
- `color`：`颜色`、`配色`、`色号`、`色系`；
- `brand`：`品牌`、`牌子`、`厂牌`；
- `origin`：`产地`、`原产地`、`哪里生产`、`哪国生产`、`国产还是进口`。

- 仅识别出一个字段且等于该任务的隐藏字段：返回冻结的 `oracle_turn.answer`，记为 `correct_ask`；
- 未识别出字段、识别出错误字段、或同时识别出多个字段：统一回答“我暂时没有更多信息，请根据已经说明的需求继续选择。”，记为 `incorrect_ask`；
- 不调用工具：记为 `no_ask`。

复合问题即使包含正确字段也不提供答案，以保证“一次只澄清一个约束”的判定明确。关键词表、统一中性回答和分类结果均写入代码或轨迹，分类不调用另一个 LLM，因此不增加成本和非确定性。

## 6. 代码边界与数据流

实现保持 V2 冻结入口不变：

- `probes/autonomous_runner.py`：固定选题、受限工具、客户端适配器、调用预算、断点续跑和轨迹落盘；
- `probes/autonomous_metrics.py`：读取 V3 轨迹与 V2 参考结果，生成 JSON/Markdown；
- `tests/test_probe_b_autonomous.py`：协议、选择、参考记录和完整 Mock 测试；
- `probes/README.md`：Linux 冒烟、续跑及指标命令。

单条轨迹的数据流为：

`under_query → 首次模型调用 → [可选 ask_user → 确定性回答 → 第二次模型调用] → 正式购物 rollout → Reward v3`

输出使用独立目录 `probes/outputs/v3/<run-id>/`。manifest 至少记录 V3 任务选择、任务哈希、参考 V2 run 路径及哈希、模型与服务地址、提示词/提问工具/购物工具哈希、调用上限、完成任务和无效任务。

轨迹必须记录原始提问、识别出的字段、是否正确、中性或 Oracle 回答类型、提问前后调用计数、完整消息和正式终局结果。

## 7. V2 参考结果处理

指标命令显式接收 V2 参考 run 目录。它读取首轮 `trajectories.jsonl`，并在存在 `supplemental_18637_oracle_ask.json` 时执行受限替换：

- 只允许替换同一 `task_id:arm` 的原始 invalid 记录；
- 补充记录自身必须有效；
- 任务哈希必须与 V2 manifest 及当前任务文件一致；
- 不删除、不改写 V2 原始文件；
- 报告中明确披露使用了第 51 次补充尝试。

所选 10 条 V2 参考基线已知为：No-Ask 严格成功 5/10、Oracle-Ask 10/10，因此 Oracle 可恢复差距为 5 题。该已知参考只用于计算恢复率，不再参与选题变化。

## 8. 成本、异常与续跑

- 真实 Pilot 最多新增 10 条轨迹，每条最多尝试一次；
- 默认 `max_steps=35`、`max_llm_calls=200`、温度 `0.0`；
- 第一次先用 `--limit-tasks 1` 冒烟，人工检查后以同一 run ID 续跑到 10；
- 已落盘任务在续跑时跳过，不重复付费；
- API、额度、网络、环境 reset/release 或本地异常产生 invalid 记录并立即停止；
- 未提问、错误提问、纯文本早停、非法动作、循环和 max steps 都是有效的 Agent 行为结果；
- 不自动重试 invalid，不自动提高调用预算；任何补跑都需要用户再次明确批准并单独审计。

## 9. 指标与继续门槛

报告至少包含：

- `ask_user` 调用率；
- 正确提问率、错误提问率及按隐藏字段分组的提问结果；
- 三条件严格成功、隐藏字段满足、真实 `wrong_purchase` 和平均环境步数；
- `correct_ask ∧ strict_success` 数量；
- 恢复题数：`Autonomous strict - No-Ask strict`；
- Oracle 差距恢复率：`(Autonomous strict - 5) / (10 - 5)`。

只有 10 条 V3 轨迹全部有效时才做结论。继续门槛必须同时满足：

1. 正确提问至少 7/10；
2. Autonomous 严格成功至少 8/10，即相对 No-Ask 至少恢复 3 题、恢复至少 60% 的 Oracle 差距；
3. 真实 `wrong_purchase` 为 0。

隐藏字段满足率继续报告但不设硬门槛，因为所选 V2 No-Ask 已达到 8/10，只有两题改善空间。Pilot 通过只表示值得继续扩大自主澄清验证；不表示已获得统计显著性，也不直接进入用户画像有效性结论。

## 10. 离线验收

本地测试不得调用付费 API，至少覆盖：

1. 固定 10 题及执行顺序不变；
2. 模型不提问时直接进入购物且以后不再获得提问工具；
3. 单字段正确问题获得冻结回答；
4. 错误、无关和复合问题只获得统一中性回答；
5. 每题最多一次提问，提问不增加环境步数；
6. `clear_query` 不出现在模型可见消息或请求中；
7. 多工具调用按第一个串行处理并留痕；
8. V2 补充记录只替换对应 invalid，错误补充记录被拒绝；
9. 调用上限、invalid 中止及同 run ID 续跑正确；
10. 10 条完整 Mock 可生成三条件报告和 PASS/FAIL/INCOMPLETE 状态。

## 11. 明确不做

- 不修改 V2 原始轨迹、manifest 或最终结果；
- 不重跑 No-Ask/Oracle；
- 不加入长期用户画像、记忆或跨任务偏好；
- 不允许购物过程中或购物动作之后追问；
- 不允许多轮澄清；
- 不用 LLM 评判问题质量；
- 不训练模型，不执行 200-task 正式评估。
