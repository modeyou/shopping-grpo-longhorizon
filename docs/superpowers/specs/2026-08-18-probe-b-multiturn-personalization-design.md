# B 探针预实验设计：澄清 + 个性化的价值验证

- 日期：2026-08-18
- 分支：`dev/innovation`（参考项目 fork）
- 状态：**待评审**

## 1. 背景与动机

- 参考项目 `shopping-grpo-longhorizon` 是单轮、非个性化的购物 Agent 后训练流水线；
- 作者在 tips 中自认砍掉了 ShopSimulator 原论文（arXiv:2601.18225）里的**多轮澄清 + 个性化**；
- ShopSimulator 论文明确：策略应为 `a_t = π(o_t, u_t, p)`，多轮模式扩展动作空间支持"与用户对话（澄清）"，`p` 为静态用户画像；
- 论文还用一条反捷径设计说明个性化数据的构造原则：**把偏好细节从用户指令中删掉，只保留商品相关线索**，防止 agent 仅凭对话推断出完整需求。

**本项目创新双线**：A = Step-level 过程奖励（训练侧）；B = 多轮澄清 + 个性化（交互侧）。本设计文档负责 B 第一阶段——**探针预实验（Pilot）**，用于在投入大工程前验证"澄清是否有可测量的价值"。

## 2. 探针目标

在 2~3 天内（无 GPU、纯 API + 环境服务）回答一个问题：
> **在"欠约束/有歧义"的购物指令上，允许 agent 向用户做 1~2 轮澄清，能否显著提升任务成功、降低错误购买，且不伤害清晰任务？**

若答案为"是"→ 正式立项 B（构造真·用户画像数据 + 澄清协议 + 多轮 SFT/GRPO + 评测扩展）；
若"否/不明显" → 记录失败模式，主线转 A。

## 3. 探针范围（刻意限定）

**做**：
- 从参考 `data/sft` 轨迹中挑任务，构造"欠约束"指令；
- 两条对比臂：基线（无澄清）vs 澄清（1~2 轮）；
- 受控版用户模拟器（规则+模板，非 LLM 角色扮演）；
- 对比指标与预设判据。

**不做（本期）**：
- 不构造真实的用户画像数据（年龄/性别/消费层级等）；
- 不做 LLM 角色扮演式自由对话用户模拟器；
- 不修改参考项目的环境协议与训练流程（仅新增探针代码）；
- 不进入 SFT/GRPO 训练。

## 4. 探针设计

### 4.1 任务选择与欠约束化（沿用论文反捷径思路）

1. 从 `data/sft` 任务中挑选 **20~30 个**（优先含品牌/型号/规格/预算等可隐藏约束的任务）。
2. 为每个任务生成**欠约束版 Query**：把 Query 中**一部分关键约束删除/模糊化**（例如"预算 300 元"→"预算不太高"；去掉品牌名；去掉容量/规格），并把**对应约束迁移为"用户未明说但事实存在"的隐藏信息**（存于探针的 FakeProfile 结构）。
3. 同时保留**清晰版（原 Query）**用于对照，验证"澄清不伤害清晰任务"。

> 说明：参考数据本身没有 user profile（已核实，sft 记录只有 system/user/assistant/tool messages，TaskFacts 由环境按 task_id 运行时恢复）。本探针用"从原 Query 中隐藏约束"**代理**用户偏好，属于明确标注的**捷径**；真正的结构化画像将在后续自建数据时按论文构造。

### 4.2 两条对比臂（同一模型、同一任务、一一配对）

- **基线臂**：教师模型只凭"欠约束 Query"交互 → 购买/放弃；
- **澄清臂**：教师模型在购买前可发 **1~2 个澄清问题** → 用户模拟器回答 → 再交互 → 购买/放弃。

### 4.3 受控版用户模拟器（规则 + 模板）

- 解析教师澄清问题 → 从 FakeProfile/TaskFacts 提取**被问到的字段**；
- 按模板生成自然中文回答，**只回答所问项、不主动多给**；
- 0 随机性、可复现、可调试。

> 完整的 LLM 角色扮演用户（论文式）留到正式立项 B 后再做；GRPO 阶段随机用户会破坏组内相对优势，这是选择受控版的关键原因。

### 4.4 运行依赖

- ShopSimulator 环境服务（端口 5700，纯 Python，**无 GPU**），按 task_id 恢复 Query 与隐藏 TaskFacts；
- 教师 LLM API（如 DeepSeek V4 Flash）；
- 探针代码新增于 **`probes/`** 目录（不动作者源码）。

## 5. 指标与判据（预先固定，防止自欺）

| 指标 | 判据（澄清臂 vs 基线臂） |
|---|---|
| 严格成功率（模糊子集） | ≥ +10 个百分点且 |
| 错误购买率（模糊子集） | 不高于基线 |
| Rubric 需求满足率（satisfied 比例） | 更高或持平 |
| 澄清轮数 / 平均步数 | 澄清 ≤ 2 轮；步数不爆炸（≤ ~1.3× 基线） |
| 清晰任务成功率 | 两臂相当（澄清不伤害） |

**决策**：
- 全部或多数判据满足 → **B 有效，正式立项**；
- 不满足 → 记录失败模式（草率购买/弱约束执行/澄清滥用等），主线转 A。

## 6. 探针产出物

- 可复用的**欠约束任务集**（含 FakeProfile）；
- 最小**澄清模拟器 + 澄清协议**原型；
- 对比结果表 + 结论（含失败模式分析）。

## 7. 诚实边界（写文档/作品集时如实标注）

- 探针验证的是"**澄清对欠约束指令的价值**"（机制层面）；
- 它**不构成**"真实画像个性化"的完整验证——那需等自建画像数据；
- 探针不评估训练（SFT/GRPO）阶段的澄清收益。

## 8. 与既定蓝图的衔接

- 探针若通过 → 在 `dev/innovation` 上扩展：Task/Goal 加 `profile` 字段（脚手架已预留可扩展字段思路）、澄清回合接入 Action Guard、Rubric 加澄清维度（可扩展评测）；
- 与 A（Step-level Reward）并行不冲突：A 在单轮基线 + GRPO 上做，B 在交互协议上做。

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 选的任务不"模糊"，澄清无增益 | 构造欠约束版时人工确认 3~5 条真正有多解/歧义；必要时扩任务量到 50 |
| 用户模拟器回答失真 | 受控版 + 抽样 5 条人工核查回答合理性 |
| 环境服务启动/连接受机器网络影响 | 探针在能连环境服务的机器上跑；纯脚本部分可先离线 |
