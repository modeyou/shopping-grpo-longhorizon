# Probe B V2 Oracle 信息价值实验结果

日期：2026-08-18

结论：**PASS，进入 Autonomous-Ask 机制验证。**

## 1. 实验问题

本实验只回答一个机制问题：购物需求缺少一个真实约束时，在第一次模型购物动作前披露该约束，是否能提高严格成功和隐藏字段满足，同时不增加错误购买。

- `no_ask`：只向模型展示单字段欠约束查询；
- `oracle_ask`：展示相同查询，并在首次模型购物动作前注入预登记的问题和回答；
- 两臂都不提供自主提问工具，因此结果不代表 Agent 已经学会提问；
- 用户画像不进入本实验。

## 3. 补充尝试审计

首轮 50 个组合全部尝试。`18637:oracle_ask` 在已经执行两步后因百炼免费额度耗尽成为基础设施无效轨迹；原始无效记录完整保留。

额度恢复后，用户明确批准只补跑这一条组合。补跑作为第 51 次补充尝试单独保存，最终指标在内存中用有效补跑替代原 invalid 记录，不修改首轮 `manifest.json` 或 `trajectories.jsonl`。因此应同时报告首轮 24/25 对的中间结果和补齐后的 25/25 对结果，不能隐藏补跑事实。

## 4. 最终结果

| 指标 | No-Ask | Oracle-Ask | 差异 |
|---|---:|---:|---:|
| 严格成功 | 19/25（76.0%） | 24/25（96.0%） | +5 题 / +20.0pp |
| 隐藏字段满足 | 22/25（88.0%） | 24/25（96.0%） | +2 题 / +8.0pp |
| 真实 `wrong_purchase` | 0 | 0 | 0 |
| 平均环境步数 | 9.88 | 8.28 | -1.60 |

配对变化：

- No-Ask 失败 → Oracle 成功：5；
- No-Ask 成功 → Oracle 失败：0；
- 净增加严格成功任务：5。

三个预登记门槛全部通过：

1. Oracle 净增加至少 3 个严格成功任务：PASS；
2. Oracle 隐藏字段满足率更高：PASS；
3. Oracle 的真实错误购买不高于 No-Ask：PASS。

## 5. 增益来自哪里

5 个严格成功翻转为：

| task | hidden field | No-Ask | Oracle | 隐藏字段是否同步改善 |
|---:|---|---|---|---|
| 6935 | color | partial alternative | gold | 否，两臂均满足 |
| 12403 | budget | repeat loop | gold | 是 |
| 13089 | color | partial alternative | gold | 是 |
| 17319 | color | partial alternative | gold | 否，两臂均满足 |
| 18637 | color | partial alternative | gold | 否，两臂均满足 |

其中 4/5 个严格成功增益来自 color，1/5 来自 budget。brand 和 origin 在该任务集上均出现明显天花板效应。因此可以说“隐藏信息具有决策价值”，但不能说四类字段的价值相同；当前信号主要由颜色约束驱动。

## 6. 结论边界

本实验支持：

> 当购物请求缺少一个真实约束时，在购物前获得该约束能够提高严格成功，并且没有增加错误购买。

本实验不支持：

- Agent 已经能识别何时需要提问；
- Agent 已经能提出命中隐藏字段的问题；
- 所有约束类型都同样受益；
- 用户画像已经有价值；
- 25 对描述性 Pilot 已达到统计显著性结论。

另一个复现限制是 `deepseek-v4-flash` 为滚动模型名，manifest 能冻结模型名、代码和任务哈希，但不能证明服务端底层 revision 永远不变。

## 7. 决策

V2 通过，下一阶段只验证 Autonomous-Ask：给模型一个受限的 `ask_user` 能力，观察它是否会问、问题是否命中隐藏字段、回答是否被利用，以及它能恢复多少 Oracle 上限。真正的长期用户画像实验继续后置。
